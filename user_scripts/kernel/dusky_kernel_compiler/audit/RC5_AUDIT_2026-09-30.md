# RC5 build and runtime audit — 2026-09-30

The strict battery profile built **7.3.0-rc5-dusky-battery**, including headers, and booted successfully in a KVM guest. The physical machine remains on RC4; the packages were not installed and its boot entries were not changed. Physical graphics, suspend, battery life and disconnected peripherals remain untested on RC5.

## Source and target

- [kernel.org release feed](https://www.kernel.org/releases.json), checked at 04:28 UTC: mainline **7.3-rc5**, released September 27; stable **7.2.8**. A copy is in the evidence directory.
- The RC archive came from the compiler's GitHub tagged-source fallback after kernel.org archive download failed. Archive decompression and source version passed; no signed archive or published archive checksum was available for this RC snapshot. Package hashes below identify the resulting local artifacts, not upstream authenticity.
- Intel Core i7-12700H, 14 firmware-exposed possible CPUs, 62.4 GiB RAM and 20 GiB ZRAM swap. Native Clang targeting resolves to Alder Lake. Neither a username nor a device identifier was added to production code.
- Installed tools checked: Python 3.14.7, Bash 5.3.20, systemd 262-1, Clang/LLD 22.1.8, GNU Make 4.4.1, pahole 1.32, mkinitcpio 42.1, DKMS 3.4.3, modprobed-db 2.51, QEMU 11.1.1 and btrfs-progs 7.1. These are development-machine observations; the final ISO package set still needs verification.
- The existing 322-name modprobed database was used. Expanded mode was not used. The complete installed Arch 7.2.7 headers configuration seeded the build when the upstream Arch configuration could not be fetched.

## Changes and evidence

| Change | Demonstrated problem and result |
| --- | --- |
| Per-run `--allow-rc` | Unattended mainline selection could not opt into RCs through a CLI flag. It now selects RC5 without changing the saved stable profile. |
| Complete offline seed | Falling back to an already-pruned running kernel cannot recover recorded disconnected drivers. The installed distribution configuration is now preferred in that situation. |
| Retained VirtIO memory | Lean bare-metal settings disabled the hotplug dependency and dropped recorded `virtio_mem`. Its dependency is preserved, and the RC5 guest bound a VirtIO memory device. |
| Retained network algorithms | The matrix disabled recorded CAKE while choosing FQ. CAKE now remains modular and FQ remains the default. |
| Child cleanup | A streaming monitor callback exception left its subprocess alive. A real subprocess regression test now verifies termination and registration cleanup. |
| Intel HID | Upstream localmodconfig did not map the Intel-prefixed Makefile target. The battery keep list now explicitly retains `INTEL_HID_EVENT`; the packaged module is present. |
| evdev RCU patch | Refreshed against RC5 without fuzz; added `rcu_barrier()` after handler unregister so deferred callbacks cannot outlive module unload. The patched builtin compiled. Actual evdev module unload was not exercised. |
| Documentation | Corrected the stale claim that battery defaults to mainline and documented RC opt-in and census retention. |

The five new regression tests all failed or errored against the original engine and all passed after the fixes. The complete suite passed **71/71 tests** in 5.483 seconds. Python syntax checks passed. TOML settings and the schema guide required no changes.

## Actual build

```sh
python dusky_kernal_compile.py --profile battery --channel mainline \
  --allow-rc --pin 7.3-rc5 --no-install --yes --no-color
```

- Final build: **32m12s**, **8,806 kbuild steps**, exit 0. No kernel compiler warnings/errors or modpost errors appeared in the final compilation.
- Kernel package: **24.0 MiB**; headers: **13.5 MiB**. This is an observed size, not a before/after size comparison.
- Pruning reduced 6,335 module configuration entries to 338 before explicit profile features. Final configuration: **353 `=m`, 2,204 `=y`**; **590 hard matrix operations verified**.
- Actual compiler command includes `-march=native`, `-O2` and ThinLTO. `NR_CPUS=14`, 300 Hz, lazy/dynamic preemption, idle tick suppression, BTF, sched_ext, MGLRU and ZRAM support are present. Rust and unused-symbol trimming are disabled as requested by the profile.
- Four soft preferences differ through dependencies or unavailable symbols: `THP_SWAP`, `PAGE_REPORTING`, `MODULE_SIG`, `CPU_THERMAL`. Recorded balloon support selects page reporting; module signing is selected by the retained signing configuration. These are not hard contract failures.
- evdev RCU and PCI PME polling patches applied. The optional scheduler-inline patch did not match RC5 and was skipped. The build therefore does not contain that optional optimization. PCI PME's longer polling interval has not been power- or wake-latency-tested on physical hardware.

## Package, boot and module checks

- Extracted the actual packages into a temporary staging root. Checked kernel release and embedded strict/RC5 profile, PKGBUILD shell syntax, systemd unit syntax and BTF decoding.
- Built installed **acpi_call 1.2.2** and **NVIDIA 615.71.09** sources through DKMS against the **packaged headers**, with isolated source/build/module directories. The existing NVIDIA 7.3 compatibility patch was present. No host DKMS registrations or modules were replaced.
- Staged depmod with the packaged System.map found **no unresolved symbols**. All **361 staged module files**, including external modules, have matching kernel vermagic. There are **240 builtin module entries**.
- Checked presence of KVM/Intel KVM, vhost, VFIO, IOMMUFD, VirtIO memory/network/filesystem/audio, i915, Wi-Fi/Bluetooth, Thunderbolt, Intel HID, CAKE, NVIDIA's four modules and acpi_call.
- Built normal and fallback initramfs images using the host's actual mkinitcpio configuration, `--moduleroot` pointing to staging and `--nopost`. Both exited 0 and passed lsinitcpio inspection: correct RC5 release, early microcode payload, module dependency indexes, init, and graphics/storage drivers. Normal contains 29 modules; fallback contains 93. NVMe and Btrfs are builtin. No `/boot` image was written.
- Booted the packaged kernel with KVM and the host CPU in a temporary Q35 guest. **18 module-loading checks passed**, including nested Intel KVM, VFIO/IOMMUFD, vhost_net, virtiofs, WireGuard, ntsync and acpi_call. VirtIO network and graphics appeared; `virtio_mem` bound to a device. An emulated NVMe device supported Btrfs mounting, writing, unmounting, read-only remounting and reading the saved content. Guest powered off normally, with no panic, Oops, BUG or unknown-symbol report.
- Boot-entry generation was exercised with temporary file-write fixtures: primary/fallback entries preserve the root filesystem arguments and remove obsolete owned arguments. Actual installation, pacman hooks, systemd-boot selection and physical boot were not executed.

The first scratch boot/initramfs attempts lacked generated depmod indexes because package extraction does not execute pacman hooks. Generating those indexes, as installation normally does, resolved the fixture failures; no production change was needed.

## Census differences and warnings

Nine recorded names have no standalone module or builtin entry:

| Names | Explanation |
| --- | --- |
| `nfnetlink` | RC5's Makefile folds it into the builtin netfilter object; `CONFIG_NETFILTER_NETLINK=y`. |
| `842_compress`, `842_decompress`, `lz4hc_compress` | The battery compression selection disables 842/LZ4HC backends; ZSTD and LZ4 remain enabled. |
| `pcspkr` | Explicitly disabled by lean profile policy. |
| `ac97_bus`, `snd_pcm_dmaengine`, `snd_soc_sdw_utils`, `snd_sof_intel_hda_sdw_bpt` | Their remaining parent-driver selection does not require them. SOF SoundWire is disabled after pruning; retained sound drivers linked without these helpers. Actual SoundWire peripherals are not certified by this test. If one is required, its parent feature needs an explicit keep. |

The census is therefore **not preserved name-for-name**. Known VM and tested hardware-driver requirements above are preserved. Both Intel graphics drivers remain because both were recorded; no attempt was made to discard one arbitrarily.

Warnings were retained and examined:

- NVIDIA's successful external build contains **111 warning lines**, including source warnings and objtool fall-through warnings. acpi_call contains **two**: a missing function prototype and missing MODULE_DESCRIPTION. These are external-source warnings, not fixed by suppressing diagnostics.
- Both mkinitcpio builds warn that no driver exports `drm_privacy_screen_register`. The pruned configuration has no ChromeOS privacy-screen driver; image creation succeeds. No physical privacy-screen functionality was tested.
- The guest reports normal out-of-tree/signature taint for acpi_call signed with the isolated audit key, which the kernel does not trust. Signature enforcement is disabled; the module loaded successfully. Host signing keys were untouched.
- localmodconfig emitted mapping warnings for Intel HID/VSEC, nfnetlink and out-of-tree acpi_call, and EOF messages for newly visible configuration questions. The final resolved config, module inventory and builds—not those intermediate messages—were checked. Intel HID is explicitly retained, VSEC is present, nfnetlink is folded into netfilter, and acpi_call passes DKMS and guest loading.
- The existing **RC4 host journal is not error-free**: NVMe partition scheduler udev rules, intentionally disabled NVIDIA/racing power rules, TLP's disabled `tlp-pd.service`, touchpad feature-report messages and DDC errors are present. These are recorded separately and were not attributed to an uninstalled RC5 kernel. Live power-management settings can override the compiler's boot-time governor/VM tuning, so battery-profile activation alone does not establish final runtime settings.
