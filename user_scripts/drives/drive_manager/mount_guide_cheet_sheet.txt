 UNIVERSAL DRIVE MANAGER & MOUNT ARCHITECTURE CHEAT SHEET (ARCH LINUX 2026)
================================================================================

This guide serves as the definitive, bleeding-edge reference for storage,
cryptography (LUKS2/dm-crypt), filesystem mount configurations, and `drives.toml`
automation under Linux Kernel 7.1+ and Arch Linux.

--------------------------------------------------------------------------------
 1. CLI USAGE & RUNTIME BEHAVIORS
--------------------------------------------------------------------------------
Universal Drive Manager (`drive_manager.py` / aliases: `unlock`, `lock`, `drive_status`):

  $ unlock <drive1> [drive2 ...]   # Decrypt & mount target drive(s)
  $ lock <drive1> [drive2 ...]     # Unmount & securely close container(s)
  $ drive_status                   # Display live status table of all drives
  $ drive_manager.py set-password  # Store/update drive passphrase in Keyring

Key Engine Capabilities:
  • Parallel Execution: When multiple drives are requested, password entry is
    collected upfront on the main thread, followed by concurrent decryption
    and mounting across all available CPU cores via ThreadPoolExecutor.
  • Dynamic User / Home Migration: Paths starting with `~` or `$HOME` dynamically
    resolve to the active user. Any legacy hardcoded `/home/<old_user>/...` paths
    are automatically re-anchored under the active user's `$HOME`.
  • Dynamic Symlink Reconciliation: Paths specified under `symlinks = [...]` in
    `drives.toml` are automatically created or healed upon mount, replacing dummy
    unmounted directories seamlessly.
  • Stale & Divergent Mount Healing: Auto-discovers any active mounts across the
    system (`findmnt -S`) matching the device, cleanly unmounting and relocating them.
  • Interactive Busy Process Resolver: If a filesystem is busy during locking,
    parses `lsof` with sudo to present locking processes and gracefully terminates them.
  • Rotational Awareness: Automatically skips `fstrim` on mechanical rotational HDDs,
    dispatching background TRIM asynchronously only to non-rotational SSD/NVMe.

 2. DRIVES.TOML CONFIGURATION SPECIFICATION
--------------------------------------------------------------------------------
Configuration File Search Priority:
  1. `$XDG_CONFIG_HOME/drive_manager/drives.toml` (or `~/.config/drive_manager/drives.toml`)
  2. `<script_dir>/drives.toml`

Schema & Field Reference:
  [drives.<drive_name>]
  type          = "PROTECTED" | "SIMPLE"     # REQUIRED: Encrypted container vs unencrypted
  mountpoint    = "~/.config/..." | "/mnt/." # REQUIRED: Target mount directory (supports ~, $VARS)
  outer_uuid    = "<UUID>"                   # REQUIRED: Physical block partition UUID
  inner_uuid    = "<UUID>"                   # REQUIRED for PROTECTED: Decrypted filesystem UUID
  hint          = "<string>"                 # OPTIONAL: Passphrase hint for manual prompts
  fstype        = "ext4"|"btrfs"|"ntfs"|...  # OPTIONAL: Explicit kernel filesystem driver
  mount_options = ["opt1", "opt2", ...]      # OPTIONAL: List of mount flags
  symlinks      = ["~/.symlink1", ...]       # OPTIONAL: Declarative symlinks pointing to mountpoint

 4. FILESYSTEM DECISION & OPTIMIZATION MATRIX
--------------------------------------------------------------------------------

FILESYSTEM | TARGET MEDIUM     | RECOMMENDED MOUNT FLAGS                     | CRITICAL NOTES
-----------+-------------------+---------------------------------------------+------------------------------------------------
Ext4       | SSD / NVMe        | noatime, lazytime, delalloc, commit=20      | Avoid 'discard' mount flag; rely on fstrim.
Ext4       | Rotational HDD    | noatime, lazytime, delalloc, commit=20      | Delayed allocation prevents physical fragmentation.
Btrfs      | SSD / NVMe        | noatime, compress=zstd:3, discard=async     | discard=async is non-blocking and native.
Btrfs      | Rotational HDD    | noatime, compress=zstd:3, autodefrag        | autodefrag reduces seek latency (DO NOT use on SSD).
NTFS       | Dual-Boot / USB   | noatime, uid=1000, gid=1000, windows_names  | Uses native in-kernel 'ntfs' driver with -i.
           |                   | umask=002, iocharset=utf8, prealloc         | NEVER use 'force' (corrupts Windows dirty bit).
exFAT      | USB Flash / SD    | uid=1000, gid=1000, dmask=022, fmask=133    | Standard for cross-platform flash drives >32GB.
           |                   | errors=remount-ro, iocharset=utf8           |
VFAT/FAT32 | EFI Partition     | fmask=0137, dmask=0027, shortname=mixed     | Strictly for /boot/efi or tiny legacy USBs.
           |                   | utf8, errors=remount-ro                     | NEVER use 'flush' (destroys flash endurance).
F2FS       | Flash Native      | atgc, gc_merge, lazytime, compress_chksum   | Requires mkfs -O compression at format time.
           |                   | compress_algorithm=zstd:6                   | Incompatible with rotational mechanical HDDs.

--------------------------------------------------------------------------------
 5. HARDWARE & KERNEL BEST PRACTICES (LINUX 7.1+)
--------------------------------------------------------------------------------
• Kernel In-Line Decryption: On NVMe drives, configure `/etc/crypttab` with:
  `no-read-workqueue,no-write-workqueue,discard` to eliminate workqueue context-switch latency.
• Format Alignment: Always use `--sector-size 4096` during `cryptsetup luksFormat` to match
  native 4K physical NAND/HDD sector boundaries.
• Bypassing FUSE Helpers: Always mount NTFS with `mount -i -t ntfs` to force the in-kernel
  module and bypass deprecated user-space FUSE drivers (`ntfs-3g`, `ntfs3`).
• Non-Rotational SSD TRIM: Issue TRIM via background `fstrim` or `discard=async`. Mechanical
  HDDs have no flash cells; TRIM on HDDs is invalid and ignored.
